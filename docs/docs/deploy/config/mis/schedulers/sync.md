# 刷新调度器账户、用户封锁状态

:::caution

此功能已在同步封锁状态的基础之上升级为包含账户及账户下用户数据的同步功能，详情请参考 [刷新调度器账户/用户信息](#刷新调度器账户/用户信息)。

:::

由于已封锁的账户将会在slurm集群重启后被解封，且slurm集群可能在SCOW运行时重启，但并不会给scow发送信息，所以SCOW在启动时将会自动刷新一次slurm账户的封锁/解封，用户的封锁状态，同时默认在每天凌晨4点执行一次同步。

如果您对时效性有要求，可以在slurm（其它调度器也一样，此处以slurm为例）集群重启后，手动执行一下**平台调试**->**封锁状态同步**的**立刻同步调度器账户和用户封锁状态**的功能。

## 自定义配置周期性自动同步

如果您不需要自动刷新功能，也可以自定义配置：

在`config/mis.yaml`文件中，根据备注修改所需要的配置

```yaml title="config/mis.yaml"
# 周期性同步scow与调度器(如slurm)账户用户封锁状态的配置
periodicSyncUserAccountBlockStatus:
  # 是否开启
  enabled: true
  # 周期的cron表达式
  cron: "0 4 * * *"

```


## 刷新调度器账户/用户信息

因为在**SCOW**创建数据的过程中可能由于请求失败或者集群已被停用等原因造成各个集群数据无法统一，所以SCOW在原有 **同步封锁状态功能**的基础之上提供同步账户、及账户下关联的用户数据同步功能。

当前执行账户/用户同步时，会执行以下同步操作：

- **同步创建账户:** 向调度器补充创建**SCOW**中存在但调度器中未存在的账户数据
- **同步账户封锁状态:** 向调度器同步在**SCOW**中为在集群下封锁状态的账户状态
- **同步账户解封状态:** 向调度器同步在**SCOW**中为在集群下解封状态的账户状态
- **同步添加用户到账户:** 向调度器补充创建**SCOW**中存在但调度器中未存在于所属账户下的用户数据
- **同步从账户下移除用户:** 向调度器补充移出**SCOW**中未存在于所属账户下的用户数据
- **同步账户下用户的封锁状态:** 向调度器同步**SCOW**中在所属账户下为封锁状态的用户状态
- **同步账户下用户的解封状态:** 向调度器同步**SCOW**中在所属账户下为解封状态的用户状态


## 账户用户同步自动周期性开启配置

SCOW在启动时不会自动同步账户用户数据。如果您对时效性有要求，可以在slurm（其它调度器也一样，此处以slurm为例）集群重启后，手动执行一下**平台调试**->**同步账户/用户信息**的**立刻同步**的功能。

原有的[periodicSyncUserAccountBlockStatus配置](#自定义配置周期性自动同步)现在用于配置周期性自动运行同步账户用户信息功能。如果您不需要此功能或者需要修改同步周期，可通过此配置修改。

## 账户用户同步其他配置

在同步过程中为保证当前同步数据的一致性，当同步时无法对账户有关的信息进行修改。为了避免同步时间过长影响用户正常使用，提供**单次同步最长处理时间**参数来控制同步的处理时间。超时后此次同步会中止，同时记录已同步的信息。

在`config/mis.yaml`文件中，根据备注修改所需要的配置

```yaml title="config/mis.yaml"
# 同步scow与调度器(如slurm)账户用户信息的配置
syncAccountUser:
  # 单次同步最长处理时间，单位分钟
  # 会作为周期性同步的默认最长处理时间, 系统启动后不可修改。
  # 会作为手动同步的初始最长处理时间，仅支持在手动点击立刻同步时修改。
  # 类型：整数型
  # 默认 5 分钟
  maxSyncDurationMinutes: 5
  # 同步账户用户历史结果数据查询时间周期，单位天
  # 类型：整数型
  # 默认 7 天
  syncHistoryDayPeriod: 7

```
